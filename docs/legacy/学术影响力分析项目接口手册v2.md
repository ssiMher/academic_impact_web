# OpenClaw 学术影响力分析项目接口手册

## 1. 文档目的

本文档用于整理当前 OpenClaw 学术影响力分析项目中的核心脚本接口、输入输出约定、推荐调用链路、常用命令与已知限制，便于后续继续开发、调试与回归测试。

当前系统的目标不是只做 citation count，而是尽量生成可复核的学术影响力分析结果，包括：

- 找出所有引用目标论文的 citing papers
- 尽量下载 citing paper 的全文 PDF
- 从全文中定位具体引用段落
- 判断引用用途与态度
- 输出结构化 JSON 结果，便于后续汇总成报告

## 4. 各脚本接口说明

## 4.1 `fetch_contexts.py`

路径：

```text
~/.openclaw/workspace/skills/academic_impact_analyzer/fetch_contexts.py
```

### 作用

根据目标论文的 DOI、标题或 arXiv 编号，调用 Semantic Scholar 引文接口，获取目标论文在 citing papers 中的 citation contexts，并对 context 做**目标论文无关的通用打分**。

### 输入

命令行参数：

```bash
python3 fetch_contexts.py "<query>"
```

其中 `<query>` 表示**被引的目标论文**，支持：
- DOI
- arXiv 编号
- 标题

### 角色说明

- 输入参数 `query`：目标论文（被引论文）
- 输出中的 `results[].citing_title`：引用目标论文的 citing paper
- 输出中的 `results[].contexts`：该 citing paper 中与目标论文相关的 citation context

### 内部主要流程

1. `resolve_paper(query)`
   - 优先按 DOI 定位
   - 其次按 arXiv 定位
   - 否则按标题搜索

2. 调用接口：
   - `/graph/v1/paper/{paper_id}/citations?fields=contexts,title,year,venue,authors&limit=100`

3. 对每条 context 执行 `score_context()`
   - 统计标题关键词命中
   - 统计标题短语命中
   - 检查 DOI 命中
   - 检查年份命中
   - 检查 venue token 弱命中

4. 为每篇 citing paper 选出 `best_context`

### 输出 JSON 结构

```json
{
  "ok": true,
  "target": {
    "paperId": "...",
    "title": "...",
    "year": 2024,
    "venue": "...",
    "externalIds": {...}
  },
  "count": 6,
  "results": [
    {
      "target_query": "10.1145/...",
      "target_title": "...",
      "target_year": 2024,
      "target_venue": "...",
      "target_externalIds": {...},
      "citing_title": "...",
      "citing_year": 2026,
      "citing_venue": "...",
      "contexts": [
        {
          "text": "...",
          "score": 12,
          "flags": {
            "title_keyword_hits": ["..."],
            "title_phrase_hits": ["..."],
            "mentions_doi": false,
            "mentions_year": true,
            "mentions_venue_token": false
          }
        }
      ],
      "best_context": {
        "text": "...",
        "score": 12,
        "flags": {...}
      },
      "confidence": "high"
    }
  ]
}
```

### 关键字段说明

- `target`：被引目标论文
- `results`：按 citing paper 聚合的结果列表
- `results[].citing_title`：引用目标论文的论文标题
- `contexts`：该 citing paper 下的所有候选 citation contexts
- `best_context`：分数最高的一条 context
- `confidence`：按 `best_context.score` 粗略映射出的高/中/低置信度

### 当前用途

- 无 PDF 时，作为 context-only 分析依据
- 有 PDF 时，作为 `find_candidate_spans.py` 的 `context_similarity` 输入

### 当前调试行为

脚本中可临时输出：

```text
[DEBUG] GET <url>
```

用于确认失败发生在 DOI/arXiv 解析、标题搜索，还是 citations 查询阶段。

### 已知限制

- 依赖 Semantic Scholar 返回的 `contexts`
- 低分 `contexts` 可能是误匹配
- 标题搜索分支要注意 debug 打印变量名，避免 `url referenced before assignment`

### 命令示例

```bash
python3 ~/.openclaw/workspace/skills/academic_impact_analyzer/fetch_contexts.py "10.1145/3636534.3649374"
python3 ~/.openclaw/workspace/skills/academic_impact_analyzer/fetch_contexts.py "2510.08191"
```

## 4.3 `download_pdf.py`

路径：

```text
~/.openclaw/workspace/skills/download_paper_pdf/download_pdf.py
```

### 作用

尝试自动下载目标论文 PDF。

### 输入

```bash
python3 download_pdf.py "<query>"
```

支持：
- DOI
- arXiv 编号
- 标题

### 内部主要流程

1. 若输入像 DOI，则调用 `get_paper_by_doi()`
2. 若输入像 arXiv 编号，则优先直接构造 arXiv PDF 链接，并尽量补充 arXiv 元数据
3. 否则调用 `search_paper_by_title()`
4. 先尝试 Semantic Scholar 的 `openAccessPdf`
5. 若没有，再尝试 Unpaywall
6. 若论文带有 `externalIds.ArXiv`，则进一步尝试 `https://arxiv.org/pdf/<arxiv_id>.pdf`
7. 若找到 PDF 链接，则下载到 `~/paper_downloads`

### 输出 JSON 成功示例

```json
{
  "ok": true,
  "query": "...",
  "title": "...",
  "doi": "...",
  "arxiv_id": "...",
  "pdf_url": "...",
  "file_path": "~/paper_downloads/xxx.pdf",
  "paper": {
    "title": "...",
    "year": 2024,
    "venue": "...",
    "externalIds": {...}
  }
}
```

### 输出 JSON 失败示例

```json
{
  "ok": false,
  "query": "...",
  "title": "...",
  "doi": "...",
  "arxiv_id": "...",
  "error": "未找到合法开源 PDF 链接。",
  "paper": {...}
}
```

### 当前用途

- 在全文分析链中尽量自动获取 PDF

### 已知限制

- 只支持开源 PDF、Unpaywall 可返回的 PDF，或可直接访问的 arXiv PDF
- 对机构订阅论文支持不足
- IEEE TMC 等论文常常需要人工下载后放入 `~/paper_downloads`

### 命令示例

```bash
python3 ~/.openclaw/workspace/skills/download_paper_pdf/download_pdf.py "10.1145/3636534.3649374"
python3 ~/.openclaw/workspace/skills/download_paper_pdf/download_pdf.py "2410.00911"
```

## 4.5 `find_candidate_spans.py`

路径：

```text
~/.openclaw/workspace/skills/analyze_fulltext_citation/find_candidate_spans.py
```

### 作用

根据全文 JSON、目标论文标题与 DOI，以及可选的 citation contexts JSON，在 citing paper 全文中定位目标论文被引用的候选段落。

### 当前支持模式

#### 模式 A：`citation_index`

流程：
1. 识别参考文献起始页
2. 在参考文献区定位目标论文条目
3. 推断 citation index，例如 `[40]`
4. 回正文中搜索 `[40]`
5. 返回命中段落及前后相邻段落

#### 模式 B：`context_similarity`

流程：
1. 读取 `fetch_contexts.py` 生成的 JSON
2. 按 `citing_title` 过滤到目标 citing paper
3. 提取 `best_context.text` 与 `contexts[].text`
4. 与正文段落做轻量 token overlap 匹配
5. 保留 `matched_context` 与 `context_overlap_score`

#### 模式 C：`keyword_fallback`

当前两种方式不足时：
- 根据目标标题关键词与 DOI 在正文中进行启发式兜底召回

### 当前输入

```bash
python3 find_candidate_spans.py <fulltext_json_path> <target_title> [target_doi] [contexts_json_path] [citing_title]
```

参数说明：
- `fulltext_json_path`：`extract_text.py` 产出的全文 JSON
- `target_title`：被引目标论文标题
- `target_doi`：可选，被引目标论文 DOI
- `contexts_json_path`：可选，`fetch_contexts.py` 的输出文件
- `citing_title`：可选，用于从 contexts JSON 中筛选对应 citing paper

### 当前输出 JSON 结构

```json
{
  "ok": true,
  "mode": "citation_index+context_similarity",
  "reference_start_page": 16,
  "citation_index": "40",
  "citation_meta": {...},
  "context_count": 1,
  "context_candidate_count": 1,
  "count": 20,
  "spans": [
    {
      "page": 4,
      "span_index": 4,
      "text": "...",
      "score": 100,
      "match_type": "citation_index_exact",
      "citation_index": "40",
      "keyword_hits": [],
      "evidence": [
        "citation_index_exact",
        "context_similarity",
        "keyword_fallback"
      ],
      "matched_context": "...",
      "context_overlap_score": 0.7143
    }
  ]
}
```

### 关键实现点

- `find_reference_start_page()`：只在文后部分页面中检测参考文献开始页
- `extract_possible_indices()`：提取形如 `[40]` 或 `40.` 的编号
- `pick_best_index_near_signal()`：若检测到目标 DOI/关键词出现在 `[41]` 之前，可推断目标编号为 `40`
- `find_spans_by_context_similarity()`：基于 `fetch_contexts.py` 输出做全文相似定位
- `dedup_candidates()`：不再简单丢弃重复段，而是合并证据到 `evidence`
- `matched_context` / `context_overlap_score`：保留 context 命中证据

### 已验证样例

在论文：

`Fine-Grained Head Orientation Tracking Using Head-Mounted Acoustic Devices`

引用：

`MoiréVision: A Generalized Moiré-based Mechanism for 6-DoF Motion Sensing`

这一 case 中，当前结果已验证为：

- `reference_start_page = 16`
- `citation_index = 40`
- `context_count = 1`
- `context_candidate_count = 1`
- `page 4, span 4` 为精确命中段落
- `page 4, span 4` 的 `evidence` 同时包含：
  - `citation_index_exact`
  - `context_similarity`
  - `keyword_fallback`
- `context_overlap_score = 0.7143`

### 当前限制

- 仍依赖 PDF 抽取质量
- 参考文献粘连时虽可做推断，但不保证所有论文都稳定成功
- 当前 `context_similarity` 是轻量 token overlap，不是 embedding 级语义检索

### 当前命令示例

```bash
python3 ~/.openclaw/workspace/skills/analyze_fulltext_citation/find_candidate_spans.py \
  /tmp/fulltext_fine_head.json \
  "MoiréVision: A Generalized Moiré-based Mechanism for 6-DoF Motion Sensing" \
  "10.1145/3636534.3649374" \
  /tmp/contexts_moirevision.json \
  "Fine-Grained Head Orientation Tracking Using Head-Mounted Acoustic Devices" \
  > /tmp/candidate_spans_fine_head.v6.json
```

## 4.6 `analyze_fulltext.py`

路径：

```text
~/.openclaw/workspace/skills/analyze_fulltext_citation/analyze_fulltext.py
```

### 作用

对 `find_candidate_spans.py` 输出的候选段落做语义分析，判断哪些段落真正引用了目标论文，并输出结构化 findings。

### 当前分析流程

#### 第一阶段：本地 27B 分析

输入：
- 目标论文标题
- 目标年份
- 引用论文标题
- 候选段落列表

输出：
- 自然语言中文分析

#### 第二阶段：DeepSeek JSON 整理

输入：
- 本地 27B 的自然语言分析

输出：
- 严格 JSON

说明：
- 这里的双阶段仅针对 `analyze_fulltext.py` 内部的全文引用语义分析。
- 不应把飞书侧整条“发现 -> 下载 -> 分析”会话流程理解成“直接让模型生成最终学术影响力长报告”。

### 输入方式

当前脚本要求一个 JSON 字符串作为命令行参数：

```bash
python3 analyze_fulltext.py '<payload_json>'
```

## 5. 推荐调用链路

## 5.1 主通道：全文分析

推荐流程：

1. `list_papers.py`
   - 列出所有 citing papers

   - 获取 citation contexts
   - 输出到 `/tmp/contexts_xxx.json`

   - 同时利用：
     - `citation_index`
     - `context_similarity`
     - `keyword_fallback`

   - DeepSeek 输出结构化 JSON

当前已验证的链路样例：


### 6.10 运行统一总控流水线

```bash
python3 ~/.openclaw/workspace/skills/academic_impact_analyzer/run_pipeline.py \
  "10.1145/3636534.3649374" \
  --max-papers 5 \
  --scan-limit 15
```

说明：

- `--max-papers` 表示最终希望保留多少篇 citing paper 结果
- `--scan-limit` 表示最多向前扫描多少篇 citing paper；若不传，默认是 `max-papers` 的 3 倍
- 总控现在会优先保留信息量更高的结果（如 `mention_only`、`reference_only`、`fulltext_analyzed`），若不足，再用 `context_only` 补齐
- 每篇 citing paper 的 PDF 下载查询顺序为：`DOI -> ArXiv -> 标题`

默认会在 `/tmp/academic_impact_runs/<时间戳>_<query_slug>/` 下输出：

- `list_papers.json`
- `contexts.json`
- `summary.json`
- `report_summary.json`
- `report_summary.md`
- 每篇 citing paper 的独立子目录：
  - `download.json`
  - `fulltext.json`
  - `candidate_spans.json`
  - `analyze_payload.json`
  - `fulltext_analysis.json`
  - 或 `context_fallback.json`

总控 `summary.json` 中每篇 citing paper 当前可能出现的 `status` 包括：

- `fulltext_analyzed`：已在全文中识别出可解释的引用语义段落
- `reference_only`：已在参考文献中定位到目标论文，但正文中未找到可复核的对应引用段落
- `mention_only`：正文存在弱命中；当前可输出轻量结论（如 grouped literature mention），但不足以支撑更强的引用语义判断
- `fulltext_no_finding`：已完成全文扫描，但未找到足够可靠的正文引用证据
- `context_only`：未获得全文 PDF，仅保留 citation context fallback

## 7. 已知问题与限制

### 7.1 PDF 文本抽取不稳定

常见现象：
- 双栏拼接
- 断词
- 参考文献粘连

### 7.2 开源 PDF 下载能力有限

- 主要依赖 Semantic Scholar 的 `openAccessPdf`
- 次要依赖 Unpaywall
- 机构订阅论文通常仍需手工下载

### 7.3 `find_candidate_spans.py` 已整合 `context_similarity`

当前已稳定的定位通道为：
- `citation_index`
- `context_similarity`
- `keyword_fallback`

当前下一步优化重点不再是“是否接入 contexts”，而是：
- 提升 `context_similarity` 的相似度质量
- 调整排序与阈值
- 用更多论文做回归测试

### 7.4 `analyze_fulltext.py` 的输入方式仍偏工程测试态

- 当前 `payload_json` 直接走命令行字符串
- 后续更适合改为读取 JSON 文件
